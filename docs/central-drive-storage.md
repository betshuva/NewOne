# אחסון מרכזי ב־Google Drive

חשבון האחסון: `betshuva@betshuva.com`. הקבצים נשמרים באזור נתוני האפליקציה
(`appDataFolder`) של החשבון, בשמות אקראיים ובצורה מוצפנת. הם אינם מופיעים
כתיקייה רגילה ב־My Drive. מצב ההעברה מופיע ב־`admin-storage.html` למנהלי המערכת.

## שמירה וקריאה

- `central_drive_account` שומר הרשאת OAuth מוצפנת בנפרד מהגיבוי האישי.
- `central_drive_objects` משייך כל עצם לקובץ ולבעליו, עם מפתח אקראי נפרד
  מוצפן במפתח השרת. גוף הקובץ מוצפן ב־AES-256-GCM, כולל קשירה למזהה הקובץ והמשתמש.
- מועברים רק קבצים מאושרים, שלא נמחקו ושאינם ממתינים לסריקה, של משתמשים
  ללא Drive אישי מחובר ושיעד האחסון שלהם אינו אישי. חיבור אישי עוצר העברות
  חדשות לאחסון המרכזי; עותקים מרכזיים קיימים נשמרים עד אימות ההעברה לאישי.
- העלאה ניתנת לחידוש ומשתמשת במזהה Drive ששוריין ונשמר מראש. כך ניתן לשחזר
  לאחר אתחול או למחוק גם אם התהליך נעצר אחרי ש־Google קיבל את הקובץ.
- הורדה מלאה ובדיקת הצפנה, גודל ו־SHA-256 קודמות לסימון הקובץ כמאומת.
- לפני הסרת העותק המקומי, הקובץ מורד ונבדק שוב תחת נעילת רשומת המקור.
  כשל בעדכון מסד הנתונים לאחר ההסרה משחזר את הבתים המקומיים.
- הכתובות הקיימות, בדיקות הסינון, גישה למסמכים פרטיים ועותקים נפרדים לנמענים
  ממשיכים לפעול. סרטונים תומכים בבקשות טווח ומטמון מוצפן מוגבל בנפח ובזמן.
- השרת ממשיך לשמור מסד נתונים, מפתחות, קבצים בבדיקה ומטמון זמני.
  יש לגבות את מסד הנתונים ואת `BACKUP_TOKEN_ENCRYPTION_KEY` בנפרד; קובצי הענן לבדם אינם ניתנים לשחזור.

## מחיקה ותקלות

מחיקת רשומת קובץ, פינוי תוכן או הסרת הבעלים מסמנים את העצם למחיקה בענן
באותה עסקה. רשומת המחיקה שורדת את מחיקת המשתמש/הקובץ. עובד הרקע ממשיך
לנסות מחיקות שנכשלו. קובץ שנמחק או נחסם אינו נמסר מהענן.
נעילה משותפת לעובדי ההעברה והמחיקה מונעת מחיקה בזמן העלאה.

כשל בהעברה או באימות משאיר את המקור זמין וקובע ניסיון חוזר לאחר חמש דקות.
יתרת המכסה נבדקת לפני העברה. השהיית העברות חדשות אינה משביתה קריאה של קבצים קיימים
או טיפול במחיקות. מסך הגיבוי האישי מונע ביטול של הרשאת חשבון החברה כל עוד הוא
מוגדר לאחסון המרכזי; ביטול ההרשאה ישירות ב־Google עדיין יכול להפסיק את הגישה.

## תפעול

הפקודות מופעלות מתיקיית הפרויקט, ללא הדפסת הרשאות OAuth או מפתחות:

```sh
node scripts/central-drive-storage.cjs status
node scripts/central-drive-storage.cjs pause
node scripts/central-drive-storage.cjs enable
```

`configure` מיועד להגדרה ראשונה בלבד: הוא מאמת את זהות חשבון Google מתוך
החיבור הקיים ומשאיר העברות אוטומטיות מושהות. לאחר בדיקת קובץ ראשונה מפעילים `enable`.
בדיקה ממוקדת בזמן השהיה:

```sh
node scripts/central-drive-storage.cjs migrate --file=UUID --limit=1 --allow-paused --keep-local
```

עובד השרת מטפל באצוות של חמישה קבצים, וממשיך מיד אם האצווה מלאה. אין
להריץ עותקים נוספים של השרת לצורך העברה; כלי התפעול חולק את אותה נעילת מסד נתונים.
פעולות ההעלאה אינן שולחות הודעות למשתמשים ואינן מחייבות חיבור Drive אישי לכל משתמש.

## אימות ופריסה — 30 בספטמבר 2026

זהות חשבון החברה והרשאת האחסון אומתו מול Google. קובץ אמיתי הועלה, הורד,
פוענח והושווה למקור לפני פינויו מהדיסק; לאחר הפינוי אומתו גם הכתובת הציבורית
הקיימת ובקשת טווח בתים. השירות עודכן והעברה אוטומטית של קבצים קיימים וחדשים הופעלה.
מסך הניהול נבדק בדפדפן במחשב ובמסך צר, לרבות חסימת גישה ללא הרשאת מנהל.

118 בדיקות ממוקדות עברו, כולל מסד נתונים מבודד, שחזור לאחר תקלה, מחיקה בזמן העלאה,
קובץ פגום, מכסה מלאה, בעלות, קבצים פרטיים וסריקה חוזרת בזמן שגישה ציבורית חסומה.
הרצת החבילה המלאה מצאה שלושה כשלים בבדיקות תבניות של קוד Flutter שלא שונה במסגרת זו:
שניים ב־`test/conversation-scroll-lock.test.js` ואחד ב־`test/voice-upload-deduplication.test.js`.
התקדמות ההעברה היא נתון חי; יש לבדוק במסך הניהול או בפקודת `status`.
