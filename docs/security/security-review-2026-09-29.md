## ממצא דחוף שנותר לטיפול ב־Google Cloud

קובץ `firebase-service-account.json`, המכיל מפתח פרטי תקף של חשבון שירות, היה נגיש ללא הזדהות. בדיקת HEAD בלבד החזירה 200 לפני התיקון; לא הורד תוכנו דרך האתר. גם `server.log`, קובצי תחזוקה ותלויות היו נגישים.

החשיפה נחסמה מיד במהלך הבדיקה. הכתובות, לרבות כתובת מקודדת של המפתח, מחזירות כעת 404. הקובץ הועבר אל מחוץ לתיקיית האתר, לתיקיית הגדרות פרטית עם הרשאות 0700 וקובץ 0600. השירות קורא את המיקום באמצעות `FIREBASE_CREDENTIALS_PATH`; אימות Google באמצעות המיקום החדש הצליח.

**המפתח הישן עדיין תקף. יש ליצור מפתח חלופי, להתקין ולבדוק אותו בשירות, ואז להשבית/לבטל את המפתח שנחשף.** ניסיון לבדוק את הרשאות ניהול המפתחות באמצעות IAM הוחזר עם HTTP 403 וסיבת `SERVICE_DISABLED`: שירות IAM אינו מופעל בפרויקט. לא בוצעה החלפת מפתח ולא שונו הרשאות ענן. נדרשת גישת מנהל מתאימה ב־Google Cloud להשלמת הפעולה. [הנחיות Google להחלפת מפתחות](https://docs.cloud.google.com/iam/docs/key-rotation).

ביומני Nginx הזמינים שנבדקו לא נמצאה בקשת GET מוצלחת לכתובת המפתח שנבדקה; נצפתה בדיקת HEAD שלנו. הבדיקה אינה מוכיחה שהמפתח לא הועתק בעבר ואינה מחליפה בדיקת פעילות בחשבון הענן.
