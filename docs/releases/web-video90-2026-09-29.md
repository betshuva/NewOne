# Ninety-minute video uploads and twenty-frame sampling

Web deployment: `20260929202718` (UTC build identifier).

Uploaded videos may be up to 90 minutes. The web file picker, attachment
endpoint, reverse proxy and video service impose no configured video byte-size
ceiling. Camera recording remains limited to two minutes. Image, document and
audio limits remain enforced by type after container inspection.

Selected browser files are retained as native File/Blob references and sent
through FormData rather than copied into Dart byte arrays. The authenticated
attachment endpoint streams to private temporary files, hashes incrementally,
copies approved input into local storage and cleans temporary files after
responses, parse failures and aborted writes. Pending local videos are read as
file-backed Blobs for moderation, without loading the whole source into Node
memory. File-size metadata columns support bigint. Nginx buffers no application
upload requests and has no request-body size ceiling for the application.

The video service demuxes packet timestamps and seeks to keyframes instead of
decoding every frame twice. At most 20 distinct frames are selected uniformly
between the first and last actual frames. Both endpoints are checked first in
the local classifier and downstream provider pipeline. The manifest and display
remain chronological. Short clips deduplicate repeated samples; a one-frame
clip has a single frame representing both endpoints. Missing WebM duration
metadata is supported. Oversized duration or incomplete decoding cannot produce
an approved result.

New scan manifests are capped at 20 frames. Database bounds for historical
90-frame records are retained so existing audit records are not rewritten. A
video-specific scan version prevents ordinary media-cache reuse of the old
sampling policy while preserving image-cache behavior and existing durable
scan accounting.
