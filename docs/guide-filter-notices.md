# Guide notifications for blocked file deliveries

When an approved file is refused by a recipient or group content filter, the sender receives two private messages from the guide: the file, followed by a short explanation naming the intended recipient/group and the blocked content. The explanation replies to the file. Files that fail approval, have been purged, are inaccessible to the sender, or fail the sender's current general filter are never attached. Existing preview/filter behavior remains responsible for that content.

The same notification is used for existing-file forwards through HTTP or sockets, new uploads after scanning, and delayed scan results. Partial group delivery produces one file and an explanation with a separate group heading and one line per blocked member, even when reasons match. All members are retained in the chat report; only the push preview is shortened; successful recipients continue to receive the original message. Contact permission failures and ordinary text refusals do not generate misleading file-filter notifications.

The pair is inserted atomically, in chronological order, and relayed only to the sender after commit. Access is checked before insertion and rechecked under transaction locks. The explanation remains encrypted through the standard database wrapper. A private hash in delivery_summary deduplicates identical retries for 60 seconds, including concurrent attempts. Notification failures do not change a refusal into delivery. Existing guide-chat unread and push handling is reused.

When private guide history is refreshed, recognized older single-line group reports are displayed with a separate heading and one line per original recipient/reason section, without changing stored messages. Older comma-separated name groups are preserved because names themselves may contain commas. This formatting is restricted to marked guide notices for their intended recipient; its internal marker is removed from the response.

Verification uses `test/guide-filter-notice.test.js`, `test/guide-filter-delivery.test.js`, `test/guide-filter-notice-history.test.js`, and `test/guide-filter-upload-delivery.test.js`. The optional `DOTENV_CONFIG_QUIET=true RUN_DB_TESTS=1 node -r dotenv/config --test test/guide-filter-notice.test.js` tests create and remove an isolated PostgreSQL schema containing synthetic messages. No real users are messaged by the tests.
